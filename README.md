# SIRD — Sports Injury Risk Detection from Video

AI-powered platform that analyzes athlete movement videos to detect biomechanical
risk factors, predict potential injury risk, and generate personalized training
and recovery guidance — before an injury happens.

Built as part of the Infosys Springboard Virtual Internship (June–Aug 2026).

> **Note on AI output:** All risk scores, injury-type predictions, and guidance
> generated by this platform are AI-assisted indicators for awareness and
> professional review — **not a medical diagnosis**. Always consult a qualified
> physiotherapist, doctor, or coach before acting on this data.

---

## What it does

1. An athlete uploads a short movement clip (running, jumping, landing, sprinting)
2. The video is validated, and frames are extracted (OpenCV)
3. MediaPipe detects 33 body landmarks per frame (pose estimation)
4. Joint angles, range of motion, and left/right symmetry are computed
5. A weighted model scores movement quality and predicts injury risk
6. The athlete gets **Training Guidance**, **Recovery Guidance**, and
   **Analytics** — automatically generated from their own data
7. Progress is tracked over time, and full reports can be exported as PDF/Excel

```
Upload Video → Frame Extraction → Pose Estimation → Biomechanical Analysis
     → Movement Quality Score → Injury Risk Prediction
     → Training Guidance | Recovery Guidance | Analytics (self-served)
```

## Who uses it

The platform has **two login types**:

| Role | Access |
|---|---|
| **Athlete** | Self-registers freely. Uploads videos, gets AI analysis, and sees Training/Recovery/Analytics guidance generated from their own data — no separate coach, physio, or sports scientist account needed. |
| **Admin** | Not self-registered — promoted from an existing account. Manages users (search, filter, activate/deactivate, change roles, delete), creates organizations, generates 4-digit join codes for athletes to join a team, monitors the AI pipeline, and reviews a platform-wide activity log. |

An athlete joins an organization by entering a 4-digit code (generated by an
admin, expires in 15 minutes, single-use) — this is how athletes get grouped
under a team/club without needing separate coach accounts.

### Honest note on the risk model

The Injury Risk Prediction Engine uses the **exact weighted formula** from the
original project spec:

```
Injury Risk Score =
    Biomechanical Deviations (35%)
  + Historical Injury Factors (20%)
  + Movement Asymmetry (20%)
  + Training Load Indicators (15%)
  + Fatigue Indicators (10%)
```

This is a **rule-based scoring system**, not a trained machine learning
classifier (e.g. XGBoost/Scikit-learn). No labeled injury outcome dataset was
available to train a real classifier during this internship, so the scoring
logic uses documented, explainable rules instead. This is disclosed here
deliberately rather than implied to be more than it is.

## Setup

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Edit `.env`:
```
DATABASE_URL=postgresql://user:password@localhost:5432/sports_injury_db
SECRET_KEY=replace-with-a-long-random-string
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
```

Generate a secret key:
```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Run the backend:
```bash
uvicorn main:app --reload --port 8000
```
API docs: `http://localhost:8000/docs`

### 2. Database

```bash
createdb sports_injury_db
psql sports_injury_db < db/schema.sql
```

### 3. Frontend

```bash
cd frontend
npm install
```

Create `frontend/.env`:
```
VITE_GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
```

```bash
npm run dev
```
Runs at `http://localhost:5173`

### 4. Or run everything with Docker

```bash
docker-compose up --build
```
Frontend at `http://localhost:5173`, API at `http://localhost:8000`.

### 5. Create the first Admin account

There is no public admin signup. Register normally as an athlete, then promote
that account directly in the database (one-time only — after that, admins can
promote other users from the User Management panel):

```sql
UPDATE users SET role = 'admin' WHERE email = 'your-email@example.com';
```

## Known limitations

- **Risk model is rule-based, not ML-trained** (see note above) — no labeled
  injury dataset was available to train a real classifier.
- **Joint angles are 2D estimates** from a single camera view — accuracy
  depends heavily on camera angle. A side-on shot of a landing gives far more
  reliable knee angles than a front-facing one.
- **Pipeline runs synchronously** — pose estimation and analysis happen
  in-request, not via a background job queue. Fine for short clips, would need
  optimization for production-scale concurrent video processing.
- **No real cloud deployment** — Docker/Docker Compose work locally; AWS/Azure
  deployment was never carried out.
- **No CI pipeline** — tests exist but aren't run automatically on push.
